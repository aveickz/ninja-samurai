# Ninja vs Samurai — Card Catalog App

Локальная картотека карточек для настольной игры «Ниндзя против Самураев».
Открывается напрямую в браузере как статичный HTML файл — без сервера, без сборки.

Приложение служит двум целям:
1. **Просмотр и фильтрация** карточек в браузере
2. **Подготовка к печати** — через `Ctrl+P` / диалог печати браузера карточки выводятся на бумагу в формате А4 по 9 штук (сетка 3×3). Карточки с тегом `trash` (как real-копии в родных группах, так и pseudo-копии в разделе «Корзина») в печать никогда не попадают — `wrapForPrint` фильтрует их до группировки, плюс есть CSS-страховка `.card-item[data-tags~="trash"] { display: none }` в `print.css`.

## Стек

- **Plain JS + jQuery 3.7.1** (CDN) — никаких фреймворков
- **CSS** — чистый, без препроцессоров
- **HTML** — один файл точки входа

## База данных — cards.js

Экспортирует глобальный массив `const CARDS = [...]`.
Подключается до jQuery и app.js в app.html.

### Схема одной карточки

```js
{
  id: 1,                        // Уникальный номер
  title: "Катана",              // Русское название
  types: ["weapon"],            // Массив типов (см. допустимые ниже)
  qty: 2,                       // Количество в колоде
  desc: "Дальность 1, сила 2.", // Текст эффекта
  group: "weapon",              // Группа для разделителей (один тип)
  img: "cards/card_2_katana.png", // Путь к арту относительно app.html
  titleBgColor: "#5d3c75"       // (опционально) переопределяет цвет
                                //   плашки заголовка для этой карты;
                                //   если не задан — берётся
                                //   GROUP_TITLE_COLOR[group]
}
```

### Допустимые типы

`role` | `weapon` | `trap` | `character` | `modifier` | `defense` | `stance` | `effect` | `intervention` | `aoe` | `action`

`role` — мета-карты сторон игроков (Ниндзя, Самурай); в колоде не участвуют,
рисуются отдельной группой в самом начале сетки.

### Конструкция «-ИЛИ-» в `desc`

Если в `card.desc` встречается подстрока `-ИЛИ-` (с любыми пробелами вокруг),
описание разбивается на несколько частей. Между частями вставляется
визуальный разделитель `.card-desc-or` — две градиентные линии и слово
«ИЛИ» по центру (компактный аналог `.group-divider` в палитре бумаги).
Само сочетание `-ИЛИ-` в текст не попадает.

Пример: `desc: "Атаковать оружием 2/1 -ИЛИ- передать карту союзнику."`
→ две строки текста, между ними «── ИЛИ ──».

Логика — в `buildDescContent()` в `js/app.js`, стили — в `styles/card.css`.

## Логика приложения — js/app.js

- `TYPE_META` — метаданные типов: label + color для тегов и фильтров
- `GROUP_TITLE_COLOR` — цвет верхней плашки по group
- `GROUP_ORDER` / `GROUP_LABELS` — порядок и названия групп-разделителей
- `buildCard(card)` — строит DOM-элемент `.card-item`
- `buildGroupDivider(groupKey)` — строит разделитель группы (полная ширина грида)
- `buildFilters()` — строит панель фильтров `#filter-bar`. Кнопки во
  втором ряду (типы карт) сортируются по убыванию количества карт с
  этим типом (`count(id)`, `qty` не учитывается, multi-type карта
  считается под каждым своим типом). Тай-брейк — стабильный порядок
  из `TYPE_META`. Так «Оружие» всегда первое, «Роль» — последнее.
- `buildStats()` — заполняет таблицу `#stats-table` в правом сайдбаре.
  Группы тоже сортируются по убыванию — по колонке «Карт» (сумма qty
  активных карт группы); тай-брейк — индекс в `GROUP_ORDER`.
  Псевдо-группы (Черновик, Корзина) идут после, в фиксированном
  порядке, без участия в сортировке.
- `isPlayable(card)` — вычисляемое на лету свойство (helper-функция,
  не хранится в данных карточки). Возвращает `false`, если
  `card.group` входит в `NON_PLAYABLE_GROUPS = ['role', 'character']`.
  «Игровые» карты — это активные карты (без trash и draft) минус роли
  и персонажи. В сайдбаре статистики показываем 4 числа:
  «Игровых типов / Игровых карт» (id `#stat-playable-{types,qty}`) и
  «Неигровых типов / Неигровых карт» (`#stat-other-{types,qty}`).
  В таблице групп процент в колонке «%» считается ТОЛЬКО от
  `playableQty`; неигровые группы (роли, персонажи) показывают «—»
  и помечаются классом `.stats-row--non-playable` (курсив, приглушённый
  цвет).
- `applyFilter()` — показывает/скрывает карточки и разделители, обновляет счётчик
- Фильтр: одиночный (один тип за раз), клик на активный — сброс к «Все»
- Зум: клик по `.card-item` → `transform: scale(2)` + `z-index: 100`, Escape/клик вне — закрыть

В режиме без фильтра карточки разделены по группам через `.group-divider` (занимает всю ширину грида `grid-column: 1/-1`). При активном фильтре разделители скрыты (`.group-divider--hidden`).

## Внешнее состояние — kvdb.io

Backend'а у приложения нет, но при необходимости персистентного состояния
между пользователями/устройствами используем внешний KV-стор
[kvdb.io](https://kvdb.io) — простое хранилище ключ-значение поверх REST.
Ничего локально не сохраняется (никаких `localStorage`/`sessionStorage`).

### js/kvdb.js — обёртка над API

Подключается в `app.html` ПЕРЕД `app.js`. Экспортирует `window.KVdb`:

```js
var bucket = KVdb.bucket('BUCKET_ID', 'optional_access_token');

await bucket.get(key);                  // → строка | null (404)
await bucket.getJSON(key);              // → объект | null
await bucket.set(key, value, { ttl });  // POST text/plain
await bucket.setJSON(key, obj, { ttl });// POST application/json
await bucket.del(key);                  // DELETE (404 → null)
await bucket.incr(key, 1);              // PATCH +1, возвращает новое значение
await bucket.list({ prefix, values, limit, skip, reverse });
```

Все методы — Promise. `404` для `get/getJSON/del` трактуется как
«нет ключа» и возвращает `null`. Прочие не-2xx → `reject(Error)` с
полями `.status` и `.body`.

Лимиты kvdb: ключ ≤ 128 байт, значение ≤ 16 КБ, TTL по умолчанию
1 неделя (бесплатный план).

### Конфиг — KVDB_CONFIG

Перед подключением `comments.js` в `app.html` объявлен глобальный конфиг:

```js
window.KVDB_CONFIG = {
  bucket:   '',     // id bucket'а на kvdb.io
  writeKey: null    // опциональный write_key, если bucket приватный
};
```

Если `bucket` пустой — `comments.js` молча отключается с warning'ом.

### Как создать bucket (один раз вручную)

```bash
curl --data-urlencode 'email=YOU@example.com' https://kvdb.io
# → ответ: короткий id, его и пишем в KVDB_CONFIG.bucket
```

После создания **обязательно подтвердите email** по ссылке в письме —
без верификации kvdb блокирует записи (отвечает «email address not verified»).

### Комментарии — js/comments.js

UI:
- На каждой карточке в `.card-footer` появляется кнопка-бейдж
  `.card-comments-btn` с эмодзи 💬. Класс `.card-comments-btn--has`
  включается, если у карточки есть хотя бы один комментарий —
  бейдж становится золотым, и в правом верхнем углу появляется
  красный пульсирующий кружок (`::after`), как в мессенджерах
  при непрочитанных сообщениях. Само количество комментариев
  нигде не показываем: достаточно факта наличия.
- Клик по бейджу открывает оверлей `.comments-overlay`
  (fixed-position на `body`, не масштабируется зумом карточки).
  В оверлее: список комментариев + форма «Комментарий» + «Добавить»
  (без поля «Имя» — комментарии анонимные).
- Закрытие оверлея: кнопка «×», `Escape`, или клик вне панели.
  Escape-listener висит в capture-фазе, чтобы перехватить событие
  до document-level handler'а app.js (иначе зум закрылся бы вместе
  с оверлеем).
- Бейдж и зум независимы: клик по карточке зумит, клик по бейджу —
  открывает комментарии (с `e.stopPropagation()`, чтобы не зумить).

На старте модуль одним запросом `bucket.list({ prefix: 'card_' })`
(без `values=true`) получает только список ключей вида
`card_<ID>_comments`. По ID:
- помечает соответствующие `.card-comments-btn` как `--has`,
- проставляет атрибут `data-has-comments="1"` на `.card-item`
  (включая pseudo-копии в Корзине).

Тела массивов не качаем — это самый дешёвый сценарий по трафику.
При добавлении первого комментария к карточке метка обновляется
локально (без повторного `list`).

### Фильтр «💬 Комментарии»

После того как `loadCommentedCards()` отрезолвится, `comments.js`
добавляет в третий ряд `.filter-bar` кнопку `.filter-btn--comments`
с `data-type="__comments__"`. До успешной загрузки списка ключей
кнопки нет — фильтру нечем оперировать.

Логика фильтрации живёт в `app.js`: при `activeMode === '__comments__'`
карточка видна, если у неё `data-has-comments="1"`. Переключение делает
`window.CardFilter.toggleMode('__comments__')` — публичный API из
`app.js`:

```js
window.CardFilter = {
  setMode:    function (mode) { ... },  // установить или null = «Все»
  toggleMode: function (mode) { ... },  // повторный клик снимает фильтр
  getMode:    function () { ... },
  apply:      function () { ... }
};
```

`__comments__` добавлен в `VALID_MODES`, так что фильтр живёт и в
`location.hash` — закладка/перезагрузка сохраняют выбор.

Стратегия хранения:

| Что              | Где                                 |
|------------------|-------------------------------------|
| Ключ             | `card_<ID>_comments` (ID = `card.id`) |
| Значение         | JSON-массив объектов комментариев   |

Один комментарий:

```js
{
  date:    "2026-04-30T10:15:00.000Z",  // ISO, new Date().toISOString()
  comment: "Эта стойка слишком сильная" // текст
  // author: опционально и только для совместимости со старыми
  //         комментариями — новые пишутся анонимно
}
```

Комментарии пишутся анонимно: имя автора не запрашивается и не хранится.
Старые комментарии с полем `author` корректно отображаются (показывают имя),
новые — без имени, только дата. При записи нового комментария всегда сначала
перечитываем массив с kvdb, чтобы не затереть параллельные правки с другого
устройства.

### Удаление комментария

В каждом комментарии в правом верхнем углу есть кнопка `.comment-del` (×).
Клик → `window.confirm` → `deleteComment(cardId, commentDate)`:
1. Re-load массива с kvdb (защита от гонок).
2. Поиск элемента по полю `date` (ISO-строка с миллисекундами — практически
   уникальна) и удаление через `splice`.
3. Если массив стал пустым — `bucket.del(commentsKey)` полностью убирает
   ключ. Иначе `loadCommentedCards` при следующей загрузке увидел бы
   пустой `[]` и снова пометил карту как «есть комментарии».
4. Иначе — `setJSON` сохраняет урезанный массив.
5. UI перерисовывает список и зовёт `markBadge(cardId, list.length > 0)` —
   при удалении последнего комментария бейдж и `data-has-comments` снимаются,
   карта выпадает из фильтра «💬 Комментарии».

Из консоли доступен `window.CardComments` для отладки: `bucket`, `load(id)`,
`save(id, list)`, `keyFor(id)`.

### Когда использовать kvdb

- Комментарии, заметки, оценки карт от пользователей
- Любые шаренные между устройствами правки (TODO, тэги)
- Простые счётчики/метрики

### Когда НЕ использовать kvdb

- Большие данные (значение > 16 КБ) — не лезет в один ключ
- Конфиденциальные данные — bucket без `secret_key` доступен любому,
  кто знает id; для приватного хранения используйте `secret_key`+`read_key`
- Источник правды для самой колоды — она остаётся в `cards.js`

## Что НЕ делать

- Не добавлять npm/webpack/vite/React
- Не использовать CSS-препроцессоры (Sass/Less/PostCSS) и CSS-in-JS;
  плоские .css файлы только. Нынешнего разделения
  `main.css / card.css / comments.css / print.css` достаточно — не плодите
  десяток мелких файлов.
- Не использовать TypeScript
- Не добавлять backend — всё работает как статика
- Не использовать `localStorage`/`sessionStorage` — для постоянного
  состояния используем только внешний kvdb
